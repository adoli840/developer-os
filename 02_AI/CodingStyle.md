# Coding Style

## Purpose

This document defines AI-facing coding style guidance.

## General Rules

- Prefer simple, readable code.
- Follow the existing style of the project being edited.
- Add abstractions only after repeated patterns are confirmed.
- Document setup, run, and test commands.
- Keep comments short and useful.

## Comments

Use English comments.

Do not comment on obvious code. Comment only intent, constraints, tradeoffs, or non-obvious behavior.
