# Roadmap

## Purpose

This document defines long-term direction, milestones, deadlines, priorities, and dependencies across active projects.

DeveloperOS uses this document as a Project Manager input when recommending what to work on next.

## Operating Principle

DeveloperOS should not force the developer to follow the roadmap.

DeveloperOS should provide objective evidence, identify risks, and recommend the next best action. The developer always makes the final decision.

## Priority Levels

| Level | Meaning |
|---|---|
| Critical | Work that blocks important progress or has the nearest meaningful deadline |
| High | Important work that should be completed soon |
| Medium | Useful work that can wait if higher priorities exist |
| Low | Optional or exploratory work |
| Paused | Intentionally not active |

## Recommendation Rule

When the developer requests work on a project, Codex should compare that request against:

1. Roadmap priority
2. Weekly goals
3. Project status
4. Deadlines
5. Dependencies
6. Staleness and inactivity

If another project is objectively more urgent, Codex should gently explain the reason and ask whether to continue with the requested project.
